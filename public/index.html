Conventions

  • Auth: email and password. A successful login sets an HttpOnly cookie named token holding a JWT — there are no API keys and no bearer headers. Browser clients must send credentials: 'include'. In production the cookie is Secure; SameSite=None; in development it is SameSite=Lax.
  • Roles: user and admin. The very first account ever registered becomes admin; every account after it is a user. Endpoints below are labelled public, session or admin.
  • Content type: application/json, except the four image routes (meal create/update, blog create/update, user profile update) which take multipart/form-data, and the Stripe webhook which takes a raw body.
  • Ids are MongoDB ObjectIds — 24 hex characters.
  • Images are uploaded to Cloudinary and stored on the document as a secure_url plus a cloudinaryId used for later deletion. Accepted types are JPEG, JPG, PNG and WEBP.
  • Times are ISO 8601 UTC. Reminder times are converted to UTC on write and rendered back in the reminder's own IANA timezone, which defaults to Africa/Lagos.
  • Money is Nigerian naira. Orders add 10% tax and a flat ₦300 shipping charge; Stripe line items are converted to kobo.
  • Pagination is ?page= and, where supported, ?limit=. Responses carry numOfPages and a total count whose key varies by resource (totalMeals, totalOrders, totalUsers, …).
PATCH from a browser. The CORS layer advertises GET, POST, PUT, DELETE, OPTIONS — PATCH is not on the list, so a cross-origin PATCH fails its preflight even though the route exists. Same-origin calls, curl and server-to-server clients are unaffected.

Errors & limits

Two envelopes are in use. Errors thrown by a route reach the shared handler and come back as msg; errors caught inside a controller are returned directly as message. Check for both.

{ "message": "Meal not found" }

Auth

Register, log in, receive a cookie. Google OAuth is a separate, optional grant used only for Calendar sync — it is not a sign-in method.

POST /api/v1/auth/register publicCreate an account

Body: fullName*, email* (unique), password* (minimum 8 characters). The role field in the body is ignored and overwritten — the first account created becomes admin, all others user.

Request
{ "fullName": "Jane Doe", "email": "you@example.com", "password": "correct-horse" }
201
{ "msg": "user created" }

Errors: 401 when the password is shorter than 8 characters; 500 on a duplicate email.

POST /api/v1/auth/login publicStart a session

Body: email*, password*. Sets the token cookie for 24 hours. The JWT carries userId, role and fullName.

200
{ "msg": "user logged in" }

Errors: 401 invalid credentials — returned identically for an unknown address and a wrong password.

GET /api/v1/auth/logout publicClear the cookie

Overwrites the cookie with an already-expired value. Safe to call without a session.

200
{ "msg": "user logged out!" }
GET /api/v1/auth/google sessionBegin Calendar consent

Redirects to Google's consent screen for the calendar and calendar.events scopes, with access_type=offline and prompt=consent so that a refresh token is always issued. Navigate to it — do not fetch it.

GET /api/v1/auth/google/callback?code= sessionStore the refresh token

Exchanges the code, saves googleRefreshToken on the user and flips googleCalendarSyncEnabled to true. Always redirects; never returns JSON.

OutcomeRedirect
GrantedCLIENT_URL/create-reminder?calendar_auth=success
Denied or no refresh tokenCLIENT_URL/create-reminder?calendar_auth=failed&error=…

Google withholds the refresh token if the app is already authorised, which is why consent is forced on every pass.

POST /api/v1/auth/google/revoke sessionDisconnect Calendar

Clears the stored refresh token locally. Google's own grant is not revoked upstream — the user must remove it from their Google account to fully undo consent.

200
{ "message": "Google Calendar access revoked" }

Cart

One cart per user, enforced by a unique index. A cart holds meals, and each meal holds the subset of its ingredients the shopper actually wants — so quantities are edited per ingredient, not per meal.

Totals are not stored. The cart returns raw items; price, tax and shipping are computed at order time as Σ(price × quantity), plus 10% tax, plus ₦300 shipping.
GET /api/v1/cart/:userId sessionFetch, creating if absent

Returns the cart document directly, not wrapped. An empty cart is created on first read rather than returning 404.

200
{ "_id": "…", "userId": "…", "cartItems": [
    { "mealID": "…", "name": "Jollof Rice", "image": "https://…",
      "ingredients": [ { "name": "Rice", "quantity": 2, "price": 1200, "unit": "g" } ] } ] }
POST /api/v1/cart/sync sessionReplace the whole cart

Body: userId*, cartItems*. Overwrites server state wholesale — the route a client uses to push a locally-held cart up after signing in. Last write wins.

POST /api/v1/cart/add sessionAdd or merge one meal

Body: userId*, meal*. If the meal is already in the cart its ingredients are merged and matching quantities are summed; otherwise the meal is appended.

Request
{ "userId": "…", "meal": { "mealID": "…", "name": "Jollof Rice", "image": "https://…",
    "ingredients": [ { "name": "Rice", "quantity": 1, "price": 1200, "unit": "g" } ] } }
PATCH /api/v1/cart/:userId/update/:mealID sessionSet an ingredient quantity

Body: ingredientName*, newQuantity*. A quantity of zero or less removes the ingredient, and removing the last ingredient removes the meal from the cart entirely.

DELETE /api/v1/cart/:userId/remove/:mealID sessionDrop a meal

Reminders

A reminder pairs a meal with a time and a delivery channel. Times are stored in UTC and rendered in the reminder's own zone; pending reminders are re-scheduled on every server boot.

Three channels. email sends a full HTML brief — image, ingredients, numbered steps — through Brevo. push needs a Web Push subscription. calendar writes an event into the user's Google Calendar, which requires the OAuth grant first.
POST /api/v1/reminders/ sessionSchedule one

Body: meal* (meal id), reminderTime*, notificationMethod* (email | push | calendar), timezone (IANA, defaults to Africa/Lagos), isRecurring, recurringFrequency (daily | weekly | monthly), note (≤500 chars), and subscription when the method is push.

Request
{ "meal": "66f1…", "reminderTime": "2026-08-04T17:30:00+01:00",
  "notificationMethod": "email", "timezone": "Africa/Lagos",
  "note": "Buy the peppers on the way home" }
201
{ "reminder": { "_id": "…", "reminderTime": "2026-08-04T16:30:00.000Z",
                "notified": false, "timezone": "Africa/Lagos" } }

Errors: 400 for an unknown meal id, or for push without a valid subscription. Send reminderTime with an explicit offset — a bare local string is read as UTC.

Payments

Card payments go through Stripe Checkout and are confirmed by webhook. Bank transfers create an unpaid order that an admin clears by hand.

POST /api/v1/payment/create-stripe-session sessionStart Checkout

Body: cartItems*, shippingAddress*, userId*, totalAmount. Writes an unpaid order first, then opens a Checkout session carrying that order id in its metadata. One line item per meal, priced in kobo, plus a shipping line.

200
{ "sessionId": "cs_test_a1B2…" }

Redirect the browser to Stripe with this id. Success returns to CLIENT_URL/order-success, cancel to CLIENT_URL/checkout. Note the amount is taken from the request, so it should be validated against the cart server-side before this is trusted in production.

POST /api/v1/payment/orders/place sessionOrder by bank transfer

Body: cartItems*, shippingAddress*, paymentMethod, taxPrice, shippingPrice, totalAmount, transactionId. Saved with isPaid: false and a payment result of pending; a reference of the form BT-<timestamp> is generated if none is supplied.

201
{ "order": { … },
  "message": "Order placed successfully. We will process it once your payment is verified." }

Clear it later with PATCH /orders/:orderId/payment.

POST https://mealmaster1.onrender.com/api/v1/payment/webhook publicStripe callback

For Stripe, not for clients. Mounted at the top of the stack ahead of the JSON body parser so the raw bytes survive for signature verification, and rejected with 400 if the signature does not check out.

On checkout.session.completed the matching order is marked paid, stamped with paidAt and the session id, and pushed onto the user's orders array. Every other event type is acknowledged and ignored.
